### 2. Major Features Added
- **User authentication** — register, login, logout with secure sessions (`authController.js`, `AuthContext.jsx`)
- **Financial analytics** — pie/bar/area charts + monthly summary (`Analytics.jsx`, `analyticsController.js`)
- **Monthly budgets** — create/edit/delete with progress bars and budget warnings (80%/100% thresholds) (`budgetController.js`, `BudgetCard.jsx`)
- **Recurring transactions** — weekly/monthly/yearly templates with active/inactive toggle, auto-generation (`recurringProcessor.js`, `Recurring.jsx`)
- **CSV export** — user-scoped transaction export (`exportController.js`, `Settings.jsx`)
- **Audit log page** — paginated security/activity events (`auditController.js`, `AuditLog.jsx`)
- **Privacy mode** — hides monetary values with toggle across all views; chart geometry blurred when active (`PrivacyContext.jsx`, `usePrivacyFormat` hook, `PrivacyAmount` component, `StatCard.jsx`, `BudgetCard.jsx`, `Dashboard.jsx`, `Analytics.jsx`, `Transactions.jsx`, `RecurringTransactionCard.jsx`)
- **Dark mode** — light/dark/system themes (`ThemeContext.jsx`)
- **Transaction search, filtering, and sorting** — by type, category, date range, description, amount, date (`SearchFilters.jsx`, `transactionController.js`)
- **Single transaction fetch** — GET `/api/transactions/:id` (`transactionController.getTransactionById`)
- **Database migration** — automatic v1→v2 schema upgrade with encryption of existing data (`database/init.js`)
- **Notification toasts** — success/error auto-dismissing (`Notification.jsx`)
- **Default local user** — auto-created to inherit v1 data (`local@spendwise.app`)
- **Settings page** — theme, privacy, account info, CSV export (`Settings.jsx`)

### 3. Major Technical Changes
- **Async migration system** (`init.js`) replaces callback-based table creation; adds Promise-based `query.js` layer with `db.ready()` gate
- **Express-session** middleware with signed cookies, `SESSION_SECRET` env var, replaces open CORS
- **Helmet** security headers middleware on all responses
- **express-rate-limit** on auth endpoints
- **dotenv** configuration; `.env.example` template for all secrets
- **AES-256-GCM encryption** utility (`encryption.js`) — descriptions encrypted at rest, with key from env or generated `.enc_key`
- **Validation utility module** (`validation.js`) — shared server-side validators for email, password, amount, type, category, date, frequency
- **Audit logger utility** (`auditLogger.js`) — async INSERT into `audit_logs` table
- **Recurring processor** (`recurringProcessor.js`) — runs at startup (`processAllDueRecurring`) and per-auth-request (`processDueRecurring`), links generated transactions via `recurring_id`
- **Custom error handler** (`errorHandler.js`) — env-aware, production-safe generic messages
- **User-scoping** — every query includes `user_id = ?` with `req.user.id` from session
- **Schema alterations** — `ALTER TABLE transactions` adds `user_id`, `description_encrypted`, `recurring_id`; existing descriptions auto-encrypted and nulled
- **API client** (`api.js`) — unified `apiFetch` with `credentials: 'include'`, 401 auto-handler, structured error objects with `.status`
- **Context providers** — `AuthProvider`/`ThemeProvider`/`PrivacyProvider` wrap app at root (`main.jsx`)

### 5. Architecture Improvements
- **Layered structure**: routes → middleware (auth) → controllers → database query layer (Promise-based), with dedicated utils for cross-cutting concerns (encryption, validation, audit, recurring)
- **Async startup**: `db.ready` promise gates server listen + `processAllDueRecurring()`, preventing race conditions
- **Context API**: separates auth, theme, and privacy concerns into independent providers
- **Unified API client**: single `apiFetch` wrapper handles auth errors, credentials, and structured responses
- **Component modularity**: 10 reusable components (StatCard, BudgetCard, ChartCard, SearchFilters, etc.) vs 2 in v1
- **Page expansion**: 3 pages → 10 pages (Dashboard, Transactions, AddTransaction, Analytics, Budgets, Recurring, AuditLog, Settings, Login, Register)
- **Migration strategy**: idempotent schema migration auto-upgrades v1 data with zero downtime
- **Event-based notifications**: decoupled toast system via `window.dispatchEvent`
- **Separation of concerns**: formatting logic extracted to `utils/format.js`, validation to `utils/validation.js`

### 7. Testing Improvements
| Aspect | V1.0 | V2.0 |
|--------|------|------|
| Test suite | None | `test_api.js` — 27 integration tests |
| Coverage | N/A | Auth flow, transactions (CRUD+getById), analytics (4 endpoints), recurring (generation, dedup, frequency advance, inactive/future), budgets (list), CSV export, audit log, logout, 401-after-logout |

### 8. Remaining Limitations
- **Categories still hardcoded** in `format.js` / `validation.js` — no custom category management (backend enforces fixed list)
- **No unit tests** — only integration script; no `npm test` script; requires manual server+DB setup
- **In-memory sessions** — `connect-sqlite3` dependency present but not configured as session store; sessions lost on restart, not cluster-safe
- **Default dev credentials** — `local@spendwise.app` / `changeme123` auto-created; must be changed after first login
- **Client-side routing** — state-based, no URL paths; no deep-linking or browser back-button support
- **No multi-currency** — hardcoded INR
- **No banking API integration** — no data import; CSV export only (no CSV import)
- **No mobile app** — web-only
- **Rate limiting** only on auth endpoints, not general API
- **Single-node design** — SQLite file DB, no horizontal scaling
- **Encryption key management** — random `.enc_key` generated if env unset; encrypted data becomes unreadable after restart without externalized key
- **No automated test pipeline** — no CI/CD config visible
