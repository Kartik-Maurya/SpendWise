## V2.0 — SpendWise Documentation (Inspection Only)

### 1. Purpose
**SpendWise v2.0** is a secure, multi-feature personal finance management platform. It builds on the v1.0 transaction tracker by adding user accounts, authentication, financial analytics, budget management, recurring transactions, CSV export, audit logging, and privacy-focused UI controls.

### 2. New Features
- **User authentication** — register/login/logout with server-side sessions (`server/routes/auth.js`, `server/controllers/authController.js`, `client/pages/Login.jsx`, `client/pages/Register.jsx`)
- **Financial analytics** — pie (spending by category), area (monthly income vs expenses), bar charts + summary (`Analytics.jsx`, `analyticsController.js`, recharts)
- **Monthly budgets** — create/edit/delete with progress tracking & warnings (`Budgets.jsx`, `BudgetForm.jsx`, `BudgetCard.jsx`, `budgetController.js`)
- **Budget warnings** — real-time alerts at 80% / 100% / exceeded (`budgetController.getBudgetWarnings`)
- **Recurring transactions** — weekly/monthly/yearly templates with active/inactive toggle (`Recurring.jsx`, `RecurringForm.jsx`, `RecurringTransactionCard.jsx`, `recurringController.js`)
- **CSV export** — user-scoped transaction export (`exportController.js`, `Settings.jsx`, `Transactions.jsx`)
- **Audit log page** — paginated security/activity events (`AuditLog.jsx`, `auditController.js`)
- **Privacy mode** — hides all monetary values across the app with a toggle (Transactions, Dashboard, Analytics, Budgets, StatCard, BudgetCard, RecurringTransactionCard); chart geometry is blurred when active (`PrivacyContext.jsx`, `usePrivacyFormat` hook, `PrivacyAmount` component)
- **Dark mode** — light/dark/system themes (`ThemeContext.jsx`)
- **Notifications** — event-based toast for success/error (`Notification.jsx`)
- **Search, filter, sort** on transactions (`SearchFilters.jsx`, `transactionController.getAllTransactions`)
- **Loading/empty states, confirmation modals, form validation**
- **Settings page** — theme, privacy, account info, CSV export; linked from Navbar (`Settings.jsx`)
- **Database migration** — auto-migrates v1 schema, encrypts existing descriptions, creates default local user (`database/init.js`)
- **`test_api.js`** — 27 integration tests (`server/test_api.js`)

### 3. Modified Features
- **Dashboard** — redesigned with charts, budget overview, warnings, StatCards (`Dashboard.jsx`)
- **Transactions** — now auth-gated, user-scoped, encrypted descriptions; inline edit supports recurring linking; added search/filter/sort (`Transactions.jsx`, `transactionController.js`)
- **TransactionForm** — added "Make Recurring" option and loading/disabled states (`TransactionForm.jsx`)
- **API layer** — auth-aware with `credentials: 'include'`, 401 auto-logout, structured error handling (`api.js`)
- **Routing** — App gates unauthenticated users to Login (client-side state routing, not URL-based) (`App.jsx`)
- **Database init** — now Promise-based with async migration, not just table creation (`database/init.js`, `database/query.js`)

### 4. Frontend Architecture
- **Framework**: React 18 + Vite (ESM), dev server :3000, `/api` proxy → :5000 (`vite.config.js`)
- **State management**: React Context API — `AuthContext` (auth session), `ThemeContext` (light/dark/system w/ localStorage), `PrivacyContext` (toggle) (`contexts/`)
- **Routing**: client-side state routing in `App.jsx` (switch-based, no URL routes); auth-gated (shows Login/Register when unauthenticated)
- **New dependency**: `recharts` for charts
- **Components**: Navbar, AuthForm, StatCard, ChartCard, BudgetCard, BudgetForm, TransactionForm, SearchFilters, Notification, RecurringForm, RecurringTransactionCard
- **Pages (10)**: Login, Register, Dashboard, Transactions, AddTransaction, Analytics, Budgets, Recurring, AuditLog, Settings
- **Services**: `api.js` — unified `apiFetch` wrapper with cookie credentials, 401 handler, query-param builder
- **Utils**: `format.js` — currency/date formatting, hardcoded `categories` object, `getCategoryType`
- **Styling**: single `index.css` with CSS variables + `data-theme` attribute for light/dark

### 5. Backend Architecture
- **Runtime**: Node.js + Express (port 5000 via `PORT` env)
- **Server entry**: `server.js` — `dotenv`, Helmet, restricted CORS (`credentials: true`), JSON limit 10mb, express-session (HttpOnly/SameSite/24h), 7 route mounts, async-ready DB startup with `processAllDueRecurring()`, custom error handler
- **Middleware**: `auth.js` (requireAuth — checks session → `req.user`, triggers per-user recurring processing), `errorHandler.js` (production-safe generic messages)
- **Controllers (7)**: transactionController, authController, analyticsController, budgetController, recurringController, auditController, exportController — all user-scoped via `req.user.id`
- **Routes (7)**: auth, transactions, analytics, budgets, recurring, export, audit — all auth-protected except `/auth/**` and `/health`
- **Utils (4)**: `encryption.js` (AES-256-GCM), `validation.js` (email/password/amount/type/category/date/frequency), `auditLogger.js` (async writes to audit_logs), `recurringProcessor.js` (per-user + global due-recurring generation)
- **Database layer**: `init.js` (migration + Promise API `db.ready`), `query.js` (Promise-wrapped `run`/`all`/`get`)
- **Deps added**: `bcryptjs`, `connect-sqlite3` (present, not wired as session store), `dotenv`, `express-rate-limit`, `express-session`, `helmet`

### 6. Database Changes
V2.0 migrates the v1 `transactions` table and adds 4 new tables (all user-scoped):

| Table | Key columns |
|-------|-------------|
| **users** | id, name, email (UNIQUE), password_hash, created_at |
| **budgets** | id, user_id, category, amount, month, year (UNIQUE user_id+category+month+year) |
| **recurring_transactions** | id, user_id, description, type, amount, category, frequency (weekly/monthly/yearly), next_occurrence, is_active |
| **audit_logs** | id, user_id, action, resource, detail, ip_address, created_at |
| **transactions** (migrated) | + user_id, + description_encrypted (AES-256-GCM), + recurring_id; plaintext `description` nulled after encryption |

Migration (`init.js`) is idempotent: adds columns if missing, creates a default `local@spendwise.app` user (`changeme123`) for v1 data, reassigns existing transactions, encrypts plaintext descriptions. Foreign keys with `ON DELETE CASCADE` (budgets, recurring) / `ON DELETE SET NULL` (audit_logs).

### 7. API Changes
**Base**: `/api` (all authenticated endpoints require session cookie)

New routes added:
| Route | Methods | Description |
|-------|---------|-------------|
| `/api/auth/*` | POST /auth register, login, logout; GET /auth/me | Auth + session mgmt (rate-limited on login/register) |
| `/api/analytics/*` | 4 GETs | spending-by-category, monthly-spending, income-vs-expenses, summary |
| `/api/budgets/*` | CRUD + GET /warnings | 6 endpoints, month/year-scoped |
| `/api/recurring/*` | CRUD | 5 endpoints |
| `/api/export/csv` | GET | CSV download |
| `/api/audit` | GET | Paginated audit logs (`page`, `limit`) |

**Modified transactions** (now auth-gated + user-scoped):
- GET `/api/transactions` — added query params: `type`, `category`, `search`, `startDate`, `endDate`, `sortBy`, `sortOrder`
- GET `/api/transactions/:id` — **new** single-transaction endpoint (decrypts description)
- PUT `/api/transactions/:id` — accepts `recurring_id` to link to a recurring template
- Descriptions now stored encrypted (`description_encrypted`); plaintext `description` cleared

All endpoints return 401 when unauthenticated; no sensitive fields (password_hash, encrypted data) ever sent to frontend.

### 8. Security Improvements
- **Password hashing**: bcryptjs, 12 salt rounds — no plaintext storage (`authController.js`)
- **Sessions**: express-session, HttpOnly + SameSite=Lax cookies, 24h expiry, signed (`SESSION_SECRET` env, server-side `server.js`)
- **Encryption at rest**: AES-256-GCM for transaction descriptions; key from `ENCRYPTION_KEY` env or generated `.enc_key` (gitignored) — never hardcoded (`encryption.js`)
- **CORS**: restricted to `CORS_ORIGIN` env (default `localhost:3000`), `credentials: true`
- **Helmet**: CSP, X-Frame-Options, X-Content-Type-Options, HSTS, etc. (`server.js:14`)
- **Rate limiting**: login 5/15min, register 3/hour (`routes/auth.js`)
- **Authorization**: every DB query scoped to `req.user.id`; 404 on cross-user access (`transactionController.js`, etc.)
- **SQL injection**: 100% parameterized prepared statements (`query.js` wrapper)
- **Input validation**: server-side via `validation.js` on every endpoint
- **Audit logging**: login, logout, register, all CRUD events per user with IP (`auditLogger.js`)
- **Error handling**: generic messages in production; stack traces logged server-side only (`errorHandler.js`)
- **Defense-in-depth** architecture documented in README security section

- **Build**: `npm run build` (Vite) available in `client/`; `dist/` is gitignored.

- Tests use a real session cookie flow and self-clean test data prefixed `TEST_`.

### 11. Known Limitations
- **Categories still hardcoded** in `format.js` — no custom category management (despite being a stated future idea); backend `validateCategory` enforces the same fixed list
- **No unit tests** — only integration script; no test script in package.json; must run server+DB manually
- **In-memory sessions** — `connect-sqlite3` is a dependency but not configured as the session store, so sessions are lost on server restart
- **Default dev credentials** — `local@spendwise.app` / `changeme123` auto-created; must be changed after first login
- **Client-side routing** — state-based routing with no URL paths; no deep-linking or browser back-button support
- **No multi-currency** support (hardcoded INR)
- **No banking API integration** or data import beyond CSV export (no CSV import)
- **No mobile app** (React Native)
- **Rate limiting** only on auth endpoints, not on general API usage
- **Single-node design** — SQLite file DB, no horizontal scaling; in-memory sessions not cluster-safe
- `.env.example` ships a sample `ENCRYPTION_KEY`; if unset, a random one is generated (`.enc_key`), making encrypted descriptions unreadable after server restart unless key is externalized
