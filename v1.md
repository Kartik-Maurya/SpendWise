## V1.0 — SpendWise Documentation (Inspection Only)

### 1. Purpose
**SpendWise v1.0** is a minimal personal finance tracker (MVP). It lets users record income and expense transactions, view a financial summary on a dashboard, and manage (list/edit/delete) their transactions.

### 2. V1.0 Features
- **Dashboard** — balance, income, expenses, transaction count + 5 most recent transactions (`Dashboard.jsx`)
- **Add Transaction** — form for type/amount/category/date/description (`AddTransaction.jsx`, `TransactionForm.jsx`)
- **Transaction List** — all transactions with inline edit + delete-confirm flow (`Transactions.jsx`)
- **Edit Transaction** — pre-fills form, updates via PUT (`TransactionForm.jsx`, `Transactions.jsx`)
- **Delete Transaction** — confirmation dialog before deletion (`Transactions.jsx`)
- **Predefined Categories** — hardcoded in frontend (`TransactionForm.jsx:3-6`)
- **Sample data seeding** (`seed.js`)
- **Financial summary** (income, expense, balance, count) via `/summary` endpoint

### 3. Frontend Architecture
- **Framework**: React 18 + Vite (ESM), dev server on port 3000
- **Routing**: Client-side state routing (`App.jsx` holds `currentPage` state) — no URL routing
- **Components**: `Navbar.jsx` (nav links), `TransactionForm.jsx` (reusable create/edit form), `App.jsx` (layout + FAB button)
- **Pages**: `Dashboard.jsx`, `Transactions.jsx`, `AddTransaction.jsx`
- **Services**: `api.js` — thin `fetch` wrapper calling `/api/transactions`
- **Styling**: Single global `index.css` (566 lines) with CSS variables, responsive breakpoints (`vite.config.js` proxies `/api` to `localhost:5000`)
- **Dependencies**: `react`, `react-dom`, `vite`, `@vitejs/plugin-react` (no UI library, no state management library, no HTTP client library)

### 4. Backend Architecture
- **Runtime**: Node.js + Express
- **Server entry**: `server.js` (port 5000) — configures CORS, JSON parsing, transaction routes, health check, global error handler
- **Routing**: `routes/transactions.js` — 5 routes mapped to controller
- **Controller**: `transactionController.js` — logic for getAll, getSummary, create, update, delete
- **Database driver**: `sqlite3` (raw SQL queries, callback-based)
- **Cross-cutting**: CORS enabled on all routes; no auth middleware, no request logging, no rate limiting

### 5. Database
- **Engine**: SQLite file at `server/database/spendwise.db`
- **Single table**: `transactions`
  | Column | Type | Notes |
  |--------|------|-------|
  | id | INTEGER PK AUTO | Primary key |
  | type | TEXT | CHECK `income`/`expense` |
  | amount | REAL | CHECK `> 0` |
  | category | TEXT | NOT NULL (not FK - hardcoded in FE) |
  | description | TEXT | Optional |
  | date | TEXT | NOT NULL (ISO date string) |
  | created_at | TEXT | DEFAULT `datetime('now')` |
- **No `categories` table** — categories are a hardcoded JS object in `TransactionForm.jsx`
- **Seed data**: `seed.js` inserts 12 sample transactions (salary, food, transport, etc.)

### 6. API Functionality
Base path: `/api`

| Method | Endpoint | Controller Method | Description |
|--------|----------|-------------------|-------------|
| GET | `/api/transactions` | getAllTransactions | All transactions, newest first |
| GET | `/api/transactions/summary` | getSummary | income, expense, balance, count (3 sequential queries) |
| POST | `/api/transactions` | createTransaction | Create with validation (type, amount, category, date) |
| PUT | `/api/transactions/:id` | updateTransaction | Update by id (returns 404 if not found) |
| DELETE | `/api/transactions/:id` | deleteTransaction | Delete by id (returns 404 if not found) |
| GET | `/api/health` | (inline) | Health check `{status:'ok', service:'SpendWise API'}` |
| GET | `/` | (inline) | Plain text "SpendWise API is running" |

Validation (create/update): type must be `income`/`expense`, amount > 0, category & date required.

### 7. Security
- **None beyond input validation**
- CORS enabled openly (`app.use(cors())` with no origin restriction)
- **No authentication/authorization** — all endpoints public
- **No rate limiting** — brute-force/DoS unprotected
- **No HTTPS enforcement**
- **No input sanitization** — description stored as-is (potential stored XSS if rendered with `dangerouslySetInnerHTML`, though currently uses text content)
- Error handler logs stack to console but returns generic message to client
- `.gitignore` excludes `.db` and `.env` files; no env configuration actually used

### 8. Main Limitations
- **No authentication** — no user accounts; single-user only
- **No search/filter/sort** on transactions (Dashboard shows only 5 recent; list shows all unsorted except `date DESC`)
- **No categories table** — categories hardcoded in frontend, can't add new ones
- **No budgets, charts, recurring transactions, CSV export/import** (explicitly deferred to "future improvements" in README)
- **Callback-based DB code** with nested callbacks (getSummary uses 3 nested `db.get` calls)
- **No dark mode**, single responsive layout
- **Frontend validation duplicated** (frontend + backend check same fields, but no shared schema)
- **No tests** (no test framework, no coverage)
- **No `.env` usage** despite `.gitignore` listing it — backend port is hardcoded default 5000
